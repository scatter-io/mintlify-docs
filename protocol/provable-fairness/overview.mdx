title: "Provable Fairness"
description: "Learn how Scatter makes every bet independently verifiable."

Every bet placed on Scatter resolves through a randomness primitive that is verifiable onchain by anyone. There is no off-chain server choosing outcomes, and no need to trust Scatter to play fair. The result of every bet is mathematically bound to a publicly verifiable input.

Scatter combines three primitives to achieve this:

- [Verifiable Random Function](/protocol/provable-fairness/verifiable-randomness) (VRF) as the randomness source.
- [Server-seed authorization](/protocol/provable-fairness/verifiable-randomness) to verify the active seed is authorized for your wallet and expiry.
- [State commit-reveal](/protocol/provable-fairness/verifiable-randomness) as an additional mechanism used by Blackjack to hide game state during play.

Scatter combines a server seed, a client seed, and verifiable VRF randomness to determine game outcomes.

Before betting, your app receives the active server seed and a signed authorization tied to your wallet and an expiry. The game program verifies this authorization when processing the transaction.

The server seed is available before the bet resolves. Knowing the seeds alone does not reveal the future VRF output.

Blackjack additionally uses a separate secret commitment to conceal the dealer’s hole card during play.

### Changing your client seed

Open **Settings → Account**, enter a value in **Client Seed**, and select **Save changes**. Finish any active game rounds before changing it.

Leave the field blank to use each game’s automatically generated randomness. Your saved choice is stored in your browser, so check it again when using another browser or device.

### Verifying outcomes yourself

Every bet on Scatter exposes the full inputs needed for independent verification.

- The in-app **provably fair** tool checks the result.
- Onchain artifacts: All verification inputs are stored on Solana mainnet and queryable via standard RPC, so any party can verify outcomes independently of Scatter.

The onchain artifacts for a bet include:

- The VRF request and proof
- The VRF output that was consumed
- The client seed and server seed used for the bet
- Any commit-reveal hashes and revealed state (Blackjack)
- The bet parameters (game, stake, configuration)

These artifacts are sufficient to reproduce any outcome from scratch.
